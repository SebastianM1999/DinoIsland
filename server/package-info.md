# server
> Node host process: serves the web client over HTTP and runs the authoritative `ServerWorld` (src/sim/world.js) for co-op players over WebSocket.

## Files
- `staticFiles.js` — `serveStatic()`: ETag/304, brotli/gzip for text files (compressed once per file version and kept in memory), one-day caching for `/vendor/three/` and the font, and the `<link rel="modulepreload">` hints injected into `index.html` from the static import graph of its module entry (`staticImportGraph()` follows the import map for `three`), and the page's `Content-Security-Policy` header (`contentSecurityPolicy()`).
- `index.js` — HTTP static file server plus local endpoints (`/status`, `/saves*` with `saves`, dev pins); `createGameServer()` wires the game host and (with `saves: true`) the save coordinator onto one `http.Server`. Also runnable as a CLI (`node server/index.js [--port N]`, `npm start`): the development server. Co-op is Steam only, so there is no LAN door or internet tunnel.
- `devPins.js` — `handleDevPins(req, res, root)`: the dev pin tool's endpoint (`POST /__dev/pin`, `GET /__dev/pins`); writes `dev-pins/<id>.json` + `.png` (gitignored) with the git commit/branch. Answers only in a source checkout (a `.git` in the root) and only to this machine; 404 otherwise.
- `caveBake.js` — Node reader of the Hollow Mountain bakes (`assets/cave/*.bin`, `src/shared/caveBake.js`): `readCaveBake`, `bakePath`, `installCaveBakes()` (the synchronous provider `Terrain` asks; `startGameHost` installs it so the host builds a baked fixed map's walk grid in ~0.1 s instead of ~2 s).
- `gameHost.js` — `startGameHost()`: WebSocket connection handling, `hello` join/reject, message routing into `ServerWorld`, fixed-rate tick loop, snapshot broadcast and silent-client timeout. The hosted world can be swapped (`load(build)`) or closed (`unload()`); `worldless` starts without one, `admit` gates joins (and hands out persistent roster keys), `onCheckpoint` hears the world's save-worthy moments. Its world `io` offers `kick(id, reason)` (the owner's MSG.KICK): the player gets a `REJECT` with the reason and leaves the world at once, its roster key is refused until another world is loaded or the expedition closes, and the connection closes 500 ms later. Every refusal (`REJECT`) closes that way (`closeSoon`): a Steam guest handles a closed connection before the messages of the same pump and would otherwise lose the reason. While the world waits in its lobby (`world.inLobby`) no snapshots go out; timeouts use `world.idleFor(p)`.
- `saveStore.js` — `SaveStore`: the owner's expeditions on disk, one folder per world UUID, one immutable `gen-NNNNNNNNN.json` per save (temporary file, flush, rename; newest `KEEP` generations kept), damaged generations renamed `.bad` and skipped, a newer game's save never overwritten, a `.lock` file per root (one writing process). `describeIoError` turns disk errors into player-facing text.
- `saveCoordinator.js` — `SaveCoordinator`: which expedition the host serves and who may join, and as whom (owner = loopback + token from `open`/`create`, roster key `OWNER_KEY`; `private` lobby = solo, `open` = Steam friends too (an old `lan` lobby is unknown and opens as `private`); Steam guests by the bridge's authenticated Steam ID, key `steam-<id>`; other WebSocket guests (tests, the dev server) by a host-issued credential, asked for with `ident` and issued with `issue`, key `guestKey(credential)` = a hash, the credential itself is never stored), captures between ticks (`sim/worldSave.js` + `shared/saveSchema.js`), serial writes, autosave every 60 s, debounced checkpoint saves, retry with backoff, `EV.SAVED` to the owner, Save & Quit (`close`), rename, delete, `shutdown`. An expedition created or opened for friends (any lobby but `private`) starts in the lobby (`ServerWorld` `lobby`): the owner presses Start; solo plays at once. Reopening the expedition that is already open keeps its phase.
- `saveRoutes.js` — `handleSaveRoutes()`: the `/saves*` HTTP API of the coordinator (list, status, new, open, lobby, save, close, rename, delete) for the game page on this machine only.
- `lanAddress.js` — `lanAddresses(port)`: lists shareable `ws://<ipv4>:<port>` addresses, physical adapters before VM/VPN ones, de-duplicated.

## Entry points
- `createGameServer({ saves })` (index.js) — called by `desktop/host-process.js` (the desktop host, `saves: true`, listening on loopback) and by tests (`test/http-host.test.js`, `test/audio.test.js`, `test/save-host.test.js`). Returns `{ httpServer, host, saves }`; the caller decides the port and calls `listen`, and gives `saves.useRoot(dir)` the player's expedition folder.
- `startGameHost(httpServer?, { worldless, admit, onCheckpoint })` (gameHost.js; `status()` reports the protocol `version`, `open` and its `maxPlayers`) — called by `index.js` and by `desktop/steam-session.js`, which passes no HTTP server and feeds Steam peers through the returned `attachConnection(ws, addr, info)`. The returned object also has `world` (a getter: it can change), `load`, `unload`, `playerByKey`, `stop()` and `status()`.
- `npm start` / `npm run dev` run `server/index.js` directly.

## Rules
- The server only hosts; all gameplay rules live in `ServerWorld`. `gameHost.js` must not interpret game messages beyond `hello` (join) — everything else goes to `world.receive(playerId, msg)`.
- Incoming messages are capped at 8 KiB (`MAX_MSG_BYTES`, also the `ws` `maxPayload`); oversized messages close the socket, malformed JSON / non-object messages are ignored.
- Every outgoing message gets a per-recipient reliable sequence number `r`; non-snapshot messages increment it, snapshots (`MSG.SNAP`) carry the current value without incrementing. Snapshots are skipped for a socket whose `bufferedAmount` exceeds 64 KiB; reliable messages are never skipped.
- The world steps at `CONFIG.net.tickRate` with an accumulator (catch-up capped at 250 ms); snapshots go out only when `world.snapshotDue()` says so. Players silent for longer than `CONFIG.net.timeoutMs` are terminated and removed.
- Static responses go through `staticFiles.js`; everything revalidates (`no-cache` + ETag) except the vendored Three.js and the font. Dynamic `import()` targets (the game module graph) are deliberately not preloaded.
- `index.html` (200 and 304) carries the `Content-Security-Policy` from `contentSecurityPolicy()`: everything `'self'`, no `'unsafe-inline'`/`'unsafe-eval'` for scripts (the inline import map is allowed by its SHA-256, hashed over LF text like the browser's parser does), `object-src`/`base-uri`/`frame-ancestors 'none'`. Documented relaxations, each needed by the game: `style-src-attr 'unsafe-inline'` (HUD templates write `style="..."`), `connect-src ws: wss:` (the page reaches its own host over WebSocket), `blob:` for images/connect (GLTFLoader's embedded textures). New inline scripts, external origins, `eval`, WebAssembly or `data:` URLs on the page need a policy change here first; the dev-only `preview.html` pages get no policy.
- Only `src/`, `css/`, `assets/` and `index.html` are served; `/vendor/three/` maps into `node_modules/three` (or a packaged `three-addons` folder). Every resolved path is checked to stay inside its root.
- `/saves*`: reads require a loopback client; changes require loopback, `POST`, `application/json` and a localhost `Origin` on the server's own port; bodies at most 4 KiB.
- Progression belongs to the expedition: hosts never pass a client's `hello` profile to `world.join`. In a saved expedition everyone joins under a persistent roster key: `owner`, `steam-<id>` or `guest-<hash>`. A name never identifies anybody. A guest who lost its credential starts a new character (no recovery flow yet).
- Versions: every `hello` carries `v` (`PROTOCOL_VERSION`, `src/shared/protocol.js`); `gameHost.js` rejects any other version (`versionMismatch`: who has to update) before admission, so an outdated client never touches a world or a roster.
- Network exposure: a saves host (the desktop) listens on loopback only; friends reach it through Steam (`desktop/hostBridge.js`). The save and dev-pin controls check the remote address.
- The guest handshake: `hello` without `credential` -> `MSG.IDENT { world }` -> `hello { credential | null }` -> welcome, and `MSG.CREDENTIAL { world, token }` for a new guest. Hosts without saves never ask.
- Saves are captured on the event loop between ticks, never inside `world.step`; disk writes are asynchronous and one at a time per host. A failed write keeps the previous generation and the world open. Expedition folders and files are named only from validated UUIDs and counters.
- Uses `ws` and Node built-ins only; shared data comes from `src/shared/` (`config.js`, `protocol.js`, `brand.js`).

## Not here
- Game rules, AI, inventory, missions, snapshots: `src/sim/` (`world.js` and friends).
- Message formats and tunables: `src/shared/protocol.js`, `src/shared/config.js`.
- Browser solo play does not use this server: it runs `ServerWorld` in a Web Worker (`src/sim/worker.js`, started from `src/client/net/net.js`) and keeps its expeditions in IndexedDB (`src/client/net/expeditions.js`). Desktop solo is this server in the host process with a private lobby.
- The save document format and the world export/restore: `src/shared/saveSchema.js`, `src/sim/worldSave.js`.
- Steam lobbies and P2P transport: `desktop/steam-session.js` (it reuses `startGameHost`).
- Client-side networking and join UI: `src/client/net/`.
